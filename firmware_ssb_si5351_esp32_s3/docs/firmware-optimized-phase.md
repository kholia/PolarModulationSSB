# Experimental optimized-phase firmware mode

The firmware can replay a precomputed ten-second constant-envelope trajectory
generated by the offline iterative optimizer. This bypasses the live speech
DSP and Hilbert path and sends the optimized phase increments directly through
the existing Si5351 fractional-PLL update mechanism.

This is for **dummy-load or shielded bench testing only**. It is disabled at
boot because RF measurements showed that its deliberately wideband error-dump
region produces an unacceptable transmit spectrum. Good reconstructed audio
does not make this trajectory suitable for transmission.

## What is embedded

The firmware table was optimized at 16 ksample/s for:

- wanted USB audio: 300–3000 Hz
- protected transition band: 3000–4500 Hz
- phase-noise dump band: 4500–8000 Hz
- duration: 10 seconds, repeated continuously
- constant RF envelope; no drain AM

The 4.5 kHz dump boundary was chosen because the earlier Airspy capture passed
audio to approximately 4.2 kHz. The extra guard reduces the chance that the
real receiver leaks phase-coding noise into the audible channel.

The phase steps use one byte per sample. First-order error-feedback
quantization keeps cumulative phase error below 0.0124 radians. After both the
int8 and exact Si5351 fractional-b quantizers, the model reports correlation
0.99432 and SI-SDR 19.41 dB.

## Flash and test

Build and flash:

```sh
make
scripts/flash-esptool.sh /dev/tty.usbmodem11301
```

Connect a dummy load and SDR, then explicitly enable the experimental
trajectory with:

```sh
python3 scripts/polar-cat.py \
  --port /dev/tty.usbmodem11301 \
  optimized
```

The helper sends a spaced stop/configure/start sequence equivalent to:

```text
*t0*  *o1*  *t1*
```

The command sequence should report:

```text
Optimized phase trajectory: ON (takes effect on next TX)
[PHASE-OPT] Experimental 10 s trajectory; wideband dump energy; dummy-load testing only
```

Use the 2 MHz / 16 ksample/s profile. The experimental trajectory is ignored
by the 32 ksample/s profile.

Set the SDR to USB with an audio passband ending around 3.0 kHz. A receiver
filter extending past 4.5 kHz will deliberately admit the phase-noise dump
band and sound noisy.

Return to the live Hilbert/speech path with:

```sh
python3 scripts/polar-cat.py \
  --port /dev/tty.usbmodem11301 \
  live
```

That sends `*t0*`, `*o0*`, `*t1*`. Rebooting also returns to the live mode.

## Listening reference

The guarded ideal-receiver result corresponding to the firmware table is:

```sh
afplay simulate/phase-optimized-airspy-receiver.wav
```

The higher-scoring 4.0 kHz ceiling demonstration remains in
`simulate/phase-optimized-receiver.wav`, but is not the table embedded in the
firmware because it overlaps the measured edge of the Airspy audio filter.

## Regenerate the table

```sh
simulate/run_phase_optimizer.sh \
  ESP32-S3-Si5351-Sample.wav \
  simulate/phase-optimized-airspy \
  --duration 10 \
  --iterations 200 \
  --dump-hz 4500

python3 simulate/export_phase_firmware.py \
  simulate/phase-optimized-airspy-data.npz \
  src/phase_optimized_data.h \
  --report simulate/phase-optimized-firmware-metrics.json
```

Rebuild after regenerating the header.

## Required RF validation

Record raw Airspy IQ into a dummy load before considering radiated use. Check:

- occupied bandwidth and adjacent-channel power
- opposite-sideband suppression
- carrier level
- PLL response to near-pi phase changes
- any aliases around the 16 ksample/s update rate

The optimizer's reconstructed audio quality does not by itself establish that
the RF spectrum is suitable for transmission over an antenna.
